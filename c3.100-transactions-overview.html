Value

Value case

What recurring difficulty prompted this?
I have four active personal bank accounts across two geographies with over 1,400 transactions in a year (over 3.8 per day on average). I keep transaction-level reviews and mappings in the Buxfer app which allows transaction tagging, reporting and pre-defined visualisation with some data slicing. Whilst this is a major improvement vs having to track various accounts, with their banks' user experience, Buxfer's dashboards lack granularity I wanted to get better control over my personal finance. Tagging is currently largely manual as rules automation functionality within Buxfer lacks elegance.
What becomes easier, faster or better?
Making personal financial decisions i.e. large purchases, managing recurring spend such as subscriptions and direct debits, achieving my savings goal with more ease, time saving on managing transaction-level data itself.

Use case

What should this use case accomplish?
I wanted to take out all transaction-level data for the period and essentially have an "Excel Pivot" experience with it by placing a range of slicers that could provide me with any view. The inputs and the outputs of the dashboard need to match my mental model (how I query my financial data) so I don't have to adapt to an interface and user experience someone else created, but rather the data adapts to me.
Who is this for?
Currently, myself. Potentially any Buxfer user, or a user of a simlar platform (Emma, Spendee, YNAB etc.)
Potential additional features or scaling considerations
Additional functionaly: Use the tool to re-check the dataset (i.e. that each transaction is assigned only one tag). Considering adding to section 4 the top X vendors by absolute spend in the period and top X transactions. Overall performance testing: Perform multiple iterative sense-checks across the db logic (and tweak the format, but expect it’s 90:10 there). This includes cache-ing all Buxfer data again. Value generation: Identify new insights re top drivers and drainers of categies I have most control over, and find top candidates to remove or reduce, thus generating savings.
Execution

Replication guide

What happens, from request to result?
Changing any of the input controls (toggles and drop-downs) dynamically updates all outputs quickly (calculuted fields, charts etc.)
What information or context does it need?
Buxfer API is the main inputs. Buxfer itself is already authorised to connect to all my bank accounts and surface transaction-level data. The tag list and hierarchy are also already defined and is MECE (mutually exclusive and collectively exhaustive). Preferences on how inputs and outputs should be presented through iterative Codex-based development.
What comes back, and in what format?
The dashboard shows net spending, transaction count, refund rate and shares of tag, category and total expenses for the selected inputs. It compares spending with last year, highlights the biggest increases and decreases by vendor, tag or month, and plots cumulative spending against the prior year.

Quality & governance

What is allowed, and what needs approval?
Users can filter financial data, compare spending with last year, explore changes by vendor, tag or month, refresh data from Buxfer, and reset all inputs. The product is read-only: it does not edit Buxfer transactions or tags, initiate payments, or move money, neither does it surface bank account details.
What is checked, which rules apply, and what exceptions are flagged?
The dashboard checks date validity, data coverage, duplicate records and whether the delta breakdown matches the overall change. It uses Buxfer transaction types, nets refunds against spending, excludes transfers and deleted records, and compares the same dates last year. Vendors qualify for the dropdown with over €50 net spend in either year. Missing data, unavailable prior-year comparisons, unknown currencies and unclassified vendors are flagged; vendors outside the list remain in totals as “Other” but are excluded from vendor rankings.

Implementation architecture

Which tools and saved instructions make this work?
The product uses Buxfer as its financial data source, a local Python connector to retrieve transactions, and an HTML/JavaScript dashboard to calculate and display results. Saved browser data supports reopening without a fresh download. The "Buxfer financial manager" skill file and "Personal finance system" pages in Notion guide analysis and reporting, while the "Low Fidelity Wireframing" skill guides the interface. Vendor naming, grouping and calculation rules are saved in the product’s code.
