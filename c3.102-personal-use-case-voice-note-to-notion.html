Use case card:

Turn a WhatsApp voice note into a short Notion summary for easy reference and reuse.

C3.102

V1 | 31 October 2026

Value

Value case

What recurring difficulty prompted this?
Good ideas can get lost in long WhatsApp voice notes. Finding them again used to mean listening back and writing them down, or having to play back fully for tools to transcribe, which takes time.
What becomes easier, faster or better?
Distil and save the ideas from voice notes, without doing any extra work. The summary is easy to find, read and return to. Codex can also use the saved text to help with later work. This workflow essentially makes a WhatsApp note AI-legible.

Use case

What should this use case accomplish?
Turn a voice note into a short, clear text summary that keeps the main ideas and useful details.
Who is this for?
Anyone who thinks aloud in voice notes and wants to keep the ideas. It works with both sent and received notes.
Potential additional features or scaling considerations
Workflow refinement through real-life use.
Execution

Replication guide

What happens, from request to result?
A request identifies the WhatsApp voice note to summarise (within the Codex chat window, in natural language). Codex finds the message, downloads the audio and turns it into text without playing it aloud. It reads the whole note, writes a summary, saves it in Notion and returns the link. The latest 17-minute note took about 2 minutes to download, transcribe and save as a summary.
What information or context does it need?
The target WhatsApp voice note(s), access to WhatsApp and a place to save the page (a target Notion database with a default template, in this case). Summary length and formatting can be specified in the request, if different from the default.
What comes back, and in what format?
Text summary as per spec (in this case, 2–3 short paragraphs, no bullets and key points in bold, saved in a Notion page). It includes the note’s date, time and length, as well as who it was sent to or received from. Several notes can have separate summaries or one combined summary.

Quality & governance

What is allowed, and what needs approval?
Codex can access WhatsApp (via web) and Notion (via MCP), download the note, turn it into text and save the summary in the chosen location. Existing notes and edits in Notion are kept and not overwritten. Sharing the audio, sending messages or publishing the summary needs permission.
What is checked, which rules apply, and what exceptions are flagged?
Codex checks that it has the right note from the right conversation. It checks that transcription reaches the end of the recording, reads the full transcript and checks unclear words. The audio is processed directly, with no need to play it aloud. The summary keeps any uncertainty expressed by the speaker. The saved page is checked, and any reading or saving problems are reported.

Implementation architecture

Which tools and saved instructions make this work?
Codex uses WhatsApp Web to get the recording and Notion to save the summary. Faster-whisper turns the audio into text on the computer running the workflow. The latest recording was an .ogg file containing Opus audio, which it read directly. The audio stays local during that step; Codex then uses the text to write the summary. Saved instructions guide the steps and writing style.
